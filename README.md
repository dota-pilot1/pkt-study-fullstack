## 바이브 코더에서 Agent Engineer로 업그레이드하기 위한 3가지 필수 역량

FDE라는 직군이 부상하고 AX가 확산되고 있지만, 오히려 이런 시대일수록 개발자의 기본기는 더 중요합니다. AI가 구현의 상당 부분을 맡을 수는 있어도 무엇을 만들어야 하는지, 기능을 어떻게 나눌지, 어떤 순서로 진행할지, 무엇을 기준으로 검증할지는 결국 개발자가 판단해야 하기 때문입니다.

### 1. 개발 개념을 퍼즐처럼 다루는 능력

언어, DB, 네트워크, 인증, 상태 관리 등 핵심 개념을 이해하고 문제를 작은 기술 요소로 분해·조합할 수 있어야 합니다.

→ **개념 이해력**

### 2. 기능을 모듈처럼 다루는 능력

DDD, FSD, Clean Architecture, SOLID, TDD 등을 바탕으로 기능의 경계를 나누고 부분 구현·검증할 수 있어야 합니다.

→ **모듈화·부분 검증 능력**

### 3. 설계 의도를 주도적으로 관리하는 능력

기능의 목적, 책임, 제약, 비즈니스 요구를 이해하고, Agent가 구현하더라도 전체 설계 방향과 핵심 의도는 사람이 유지해야 합니다.

→ **설계 의도 관리 능력**

### 계획·문서화로 역량을 실행하기

특히 앞으로는 **계획을 세우는 능력**이 더 중요해집니다. 단순히 “이 기능 만들어줘”라고 요청하는 것이 아니라, **명확한 의도로 목표·범위·우선순위·완료 조건을 정한 계획을 세우고 문서화하는 연습**이 필요합니다.

Agent를 잘 활용하는 일도 내가 먼저 문제를 구조화하고, 작업을 나누고, 계획을 세운 뒤 그 의도를 AI에게 명확하게 전달하는 능력과 연결됩니다. 코드뿐 아니라 **개발 과정과 판단을 문서화하는 능력**도 더욱 중요해집니다.

막연히 뛰어난 개발자가 되기를 기대하기보다, 다음처럼 Bottom-up 방식으로 역량을 하나씩 쌓는 편이 현실적입니다.

```text
기본 개념 → 작은 실습 → 계획 수립 → 실제 프로젝트 적용 → Agent 활용 → 코드 리뷰 → 문서화
```

강의를 많이 듣다 보면 지식이 한꺼번에 쏟아져 머릿속에 홍수가 나는 듯할 수 있습니다. 그래서 피자나 조각 케이크처럼 학습 내용을 작은 단위로 쪼개고, 아래 흐름으로 다시 구조화할 필요가 있습니다.

```text
개념 → 작은 실습 → 실제 적용 → 실패 경험 → 리뷰 → 정리
```

AI를 컴팩트하게 활용하려면 **내 머릿속에도 구조화된 지식이 있어야 합니다.** AI에 좋은 Context를 제공하려면 나 자신이 먼저 문제와 지식을 구조화할 수 있어야 하기 때문입니다.

AI 시대의 좋은 개발자는 기본기를 버리고 AI에 의존하는 사람이 아니라, **기본기를 충분히 갖춘 상태에서 새로운 도구를 적극적으로 활용하는 사람**에 가깝습니다.

- **어깨가 좋으면서 기본 자세와 호흡을 이해하는 수영 선수**
- **공의 회전을 읽고 활용할 줄 아는 탁구 선수**
- **스텝과 거리 조절을 잘하는 복싱 선수**
- 단순히 포가 큰 것이 아니라 **기동·사격통제·승무원 숙련까지 갖춘 전차**
- 기존 전술 위에 통신망을 결합해 **스타링크 같은 인프라까지 활용하는 드론 전술**

좋은 장비가 있다고 해서 기본기가 필요 없어지는 것이 아니라, **기본기가 있을수록 좋은 장비의 성능을 훨씬 더 크게 끌어낼 수 있습니다.** AI Agent도 마찬가지입니다. Agent는 강력한 도구이지만, 개발자가 구조를 이해하지 못하고 계획을 세우지 못한다면 그 능력을 제대로 활용하기 어렵습니다.

반대로 기본기, 설계 감각, 계획 능력, 문서화 능력을 갖추면 Agent는 단순한 코드 생성기가 아니라 **개발자의 생산성과 판단 범위를 증폭시키는 장비**가 됩니다.

그래서 만든 것이 **티키타카 개발 노트**입니다. 단순히 공부한 내용을 기록하는 노트가 아니라, 사이드 프로젝트와 엔터프라이즈 프로젝트에서 얻은 개발 경험을 재사용 가능한 지식으로 축적하는 **개발 계획·학습·지식 시스템**입니다.

```text
할 일 정의 → 계획 → Agent 구현 → 검증·리뷰 → 개발 노트 → 다음 작업에 재사용
```

앞으로의 개발자는 코드를 많이 치는 사람만이 아니라, **문제를 이해하고 → 계획을 세우고 → 의도를 문서화하고 → Agent에게 일을 나누고 → 결과를 검증하고 → 다시 지식으로 축적하는 사람**에 가까워질 것입니다.

## 어떤 앱인가요?

티키타카 개발 노트는 코드를 빠르게 생성하는 것만을 목표로 하지 않습니다. 실제 프로젝트에서 발생한 할 일, 구현 과정, 리뷰 결과와 새롭게 학습한 내용을 다시 찾고 활용할 수 있는 개발 지식으로 바꿉니다.

```text
할 일 정의 → 계획 → 구현 지시·검증 → 코드 리뷰 → 노트 정리 → 다음 작업에 재사용
```

개발 속도와 학습 깊이를 **5:5 피프티 피프티**로 가져가며 다음 영역을 함께 다룹니다.

- 기본기 강화
- 언어와 프레임워크 학습
- 메이저 스펙의 이해와 적용
- 실제 기능 개발과 프로토타이핑
- 코드 리뷰와 기술 부채 해결

## 할 일 → 구현 → 리뷰 → 노트

실제 프로토타입 작업을 기준으로, 하나의 개발 경험이 다음 작업에 재사용되는 지식으로 바뀌는 과정입니다.

### 01. 할 일 — 목표와 완료 기준 정의

![Backend, Frontend, DevOps, Policy 작업과 진행률을 관리하는 티키타카 할 일 화면](docs/assets/tikitaka-todo-management.png)

Backend, Frontend, DevOps, Policy 등 작업 흐름별로 할 일을 분류합니다. 진행률, 중요도, 상태, 체크리스트, 완료 기준과 API 연결 여부를 관리해 **무엇을 왜 만들어야 하는지** 먼저 명확히 합니다.

### 02. 구현 — `for Agent {}`로 구체적인 작업 지시

![TODO API와 작업 대상 폴더를 선택해 Codex에 전달할 구현 지시를 만드는 화면](docs/assets/tikitaka-implementation-instruction.png)

선택한 TODO의 상태·세부 계획·검증 조건 API와 백엔드·프론트 작업 폴더를 하나의 구현 지시로 만듭니다. Agent는 이 지시를 따라 구현하고, 진행 상태와 검증 근거를 다시 앱에 기록합니다.

### 03. 리뷰 — 완료 계획과 통과 조건으로 코드 검증

![완료 세부 계획과 통과 조건을 선택해 Codex 코드 리뷰 요청을 만드는 화면](docs/assets/tikitaka-code-review.png)

구현이 끝난 세부 계획과 통과 조건을 선택해 Codex 리뷰 요청을 생성합니다. 백엔드·프론트 작업 경로, API 계약, 필터·정렬·페이지네이션 조건과 테스트 근거가 함께 전달되므로 구현 결과를 요구사항과 비교해 검토할 수 있습니다.

### 04. 노트 — 구현과 리뷰의 맥락을 지식으로 축적

![NOVA BSS 프로토타입의 요금제 API 구현과 코드 리뷰 문서를 계층형으로 정리한 티키타카 노트 화면](docs/assets/tikitaka-note-structure.png)

1차 메뉴 → 2차 주제 → 본문 문서 → 하위 문서 구조로 프로젝트의 맥락을 정리합니다. 요금제 API 설계, 백엔드 구현과 세부 코드 리뷰를 연결하고, Lexical의 코드 블록·표·Mermaid 다이어그램으로 구현 가능한 개발 문서를 만듭니다.

리뷰에서 확인한 개선점과 선택의 이유는 다시 노트에 반영되고, 정리된 지식은 다음 할 일의 출발점이 됩니다. 앱의 `API for LLM`과 문서 작성 예제를 이용하면 Agent도 현재 구조와 작성 규칙을 이해한 상태에서 노트를 작성하거나 수정할 수 있습니다.

## 가볍게 설치하고 공유하는 구조

| 기술 | 역할 |
| --- | --- |
| Tauri 2 | 가벼운 데스크톱 앱 패키징과 자동 업데이트 |
| Next.js 16 + React 19 | 화면과 로컬 API를 구성하는 풀스택 기반 |
| SQLite + Drizzle ORM | 별도 DB 서버 없이 노트와 작업 데이터 보관 |

앱, 기능과 기준 학습 데이터를 함께 패키징하므로 복잡한 서버 환경 없이 개인 또는 팀에 배포하기 쉽습니다. 사용자 노트는 앱 번들과 분리된 Tauri 사용자 데이터 경로에 저장되어 업데이트 이후에도 유지됩니다.

## 로컬 개발

### 요구 사항

- Node.js 20 이상
- npm
- 데스크톱 앱 빌드 시 Tauri 2 개발 환경

### 웹 개발 서버

```bash
npm install
npm run dev
```

### Tauri 데스크톱 앱

```bash
npm run tauri dev
```

## 검증

```bash
npm run lint
npm run build
npm run check:server-architecture
```

## SQLite 데이터 보존

로컬 개발에서는 프로젝트 루트의 `.data/pkt-study.db`를 사용합니다. Tauri 릴리즈 빌드는 기준 DB를 첫 실행용 seed로 패키징하고, 설치 앱은 이를 Tauri 사용자 데이터 경로에 복사해 사용합니다.

앱 업데이트나 재설치로 번들이 교체되어도 사용자 노트는 유지됩니다. 설치 앱의 백업·복원은 앱 설정의 SQLite 백업 기능을 사용합니다. `PKT_STUDY_DATA_DIR`는 Tauri가 자동으로 주입하므로 릴리즈 업데이트에서 앱 번들 경로로 변경하면 안 됩니다.

## 앞으로의 방향

MCP와 RAG를 연결해 작업과 관련된 노트를 자동으로 찾고, 팀에서 검증한 규칙과 구현 사례를 Agent가 근거로 활용할 수 있는 개발 지식 정보 시스템으로 확장할 계획입니다.
